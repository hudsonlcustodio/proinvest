# Threat Model: Connections V1.2 private beta

Assets: credentials, canonical financial records, sanitized source records and provenance. Trust boundaries: browser/API, API/PostgreSQL and file parser. There is no approved live provider.

Implemented controls: connector registry exposes only FILE_IMPORT and no financial write method; CSV input is size bounded and parsed without URLs; an allowlist limits persisted source fields; malformed financial rows are rejected; selected Strategy/instrument/account and symbol/currency/template compatibility are checked before promotion. A unique connection/external-ID index blocks altered replay, while fingerprint replay is idempotent. Promotion and staging state change share one PostgreSQL transaction. Secrets use AES-256-GCM with a random IV/tag, key version and external master key; plaintext is never returned by the API. React escapes source text; SQL uses parameters; same-origin CSP, anti-framing and no-sniff headers are preserved. Logs contain safe run IDs, state and counters, not CSV rows or secrets. Terminal staging retention defaults to 90 days; actionable rows are preserved.

Negative evidence: golden tests cover read-only capabilities, secret authentication and malformed financial values. PostgreSQL integration covers invalid rows, wrong reconciliation references, changed external IDs, concurrent promotion/rejection, counters and canonical provenance. Real Chromium QA in CI covers desktop/mobile import, resolution and Portfolio/Dashboard convergence.

Residual risks and strict boundary: this beta has no authentication, tenant/account authorization, rate limiting, managed KMS, public TLS termination, backup/restore verification or incident response process. List and action endpoints are global to the private instance. Do not expose this API publicly or use it as a multi-user service. Provider-specific OAuth scopes, terms, TLS endpoints, timeouts and retries are not implemented because no live provider is approved. Public production requires a separate gate.
